# OpenText QA Tool: FY27 Architecture & Delivery Plan

## Context
OpenText (the client) wants its basic page-validation utility to become a **content quality, link governance, accessibility, and brand compliance platform**. The goal is to cut manual QA effort by 40–60%. Pages arrive as **one ticket per page** and are QA'd one at a time.

Vigneswari (marketing-tech, not a developer) built a browser-only JS/HTML checker. It is the starting point, and its rules must carry over. Sabarinath asked Mayank to plan the build with Vigneswari and email an ETA.

**Sources:** the client FY27 roadmap (5 releases), Vigneswari's rule list, the template sample list, and the kickoff meeting.
**Decisions:** Python 3.12 + Playwright engine; a local web dashboard (FastAPI + Jinja2 + HTMX). This document is an architecture plan only.

---

## Platform Architecture (maps to the client's 4 layers)

```
qa-tool/
  app/                         Layer 4 UI: FastAPI + Jinja2 + HTMX, no JS build step
    main.py                    routes: new run, progress, report, governance uploads, history
    templates/  static/
  engine/
    runner.py                  one run = load -> extract -> validate -> score -> persist
    load/page_loader.py        Playwright: load, scroll (lazy content), expand tabs/accordions, screenshot
    extract/                   LAYER 1: PageSnapshot
      links.py                 raw href (getAttribute, NOT resolved .href), text, target, rel, bbox, region
      media.py                 img/srcset/currentSrc/naturalWidth, video/source/poster, iframes, scripts
      headings.py  metadata.py  text.py   (visible text segments with region + selector)
    rules/                     LAYER 2: validation engine, one package per rule category
      base.py                  Rule interface + declarative rule types (url_contains, attr_missing, text_match...)
      link/  content/  brand/  accessibility/  media/  template/
    http/link_checker.py       async HTTP: manual redirect following, per-host concurrency, cache
    scoring.py                 QA score, compliance score per area, severity weights
  governance/                  LAYER 3: sources (files now, integrations later)
    rules.yaml                 declarative rules editable by non-devs
    product_registry.xlsx      names, abbreviations, legacy names, trademarks
    templates/*.yaml           template definitions (detection markers, required sections, CTA placement)
    brand_standards/  cta_standards.yaml
  report/                      LAYER 4: html_report, annotate (screenshot highlights), export_xlsx/csv/pdf
  data/runs.sqlite             run history by ticket + URL (trend analysis, reviewer decisions)
  tests/  fixtures/  benchmark/
  start.bat                    one-click setup and launch for non-dev users
```

**Core model:** `Finding {rule_id, area, category, severity (critical|major|minor|info), status (issue|review|pass), message, suggestion, element_text, raw_value, selector, region, bbox, reviewer_decision}`. Every rule emits this shape, so the dashboard, screenshot highlights, scoring, and exports work without changes as rules are added.

**Design principles**
- **Declarative-first rules.** Most rules are "URL contains X", "attribute missing", or "text matches X" entries in `rules.yaml`. Python is needed only for real logic (HTTP, headings, trademark first-use). New legacy domains or terms need no code.
- **Governance as data.** The registries are Excel/YAML files uploaded through the dashboard and versioned in SQLite. Their row format already matches a future API integration.
- **Region awareness.** Each element is tagged `header | main | footer`, using selectors from the template definitions. By default only `main` is validated, with an "include global nav/footer" toggle. This stops every ticket from repeating the same footer findings.
- **PDF export** is generated by Playwright from the HTML report (`page.pdf()`), which avoids a separate PDF library.

## Dashboard Navigation (client's recommended functional QA areas)
One **Run** (ticket ID + URL, template auto-detected or overridden) produces results across all areas. The tabs filter that single result:
**Overview** (QA score, compliance score per area, severity counts, trend for this URL) · **Link QA** (with the link inventory) · **Content QA** · **Accessibility QA** · **Media QA** · **Template QA**.
Every tab has an issue table, highlights on the annotated screenshot, Confirm/Dismiss for `review` items, and Excel/CSV/PDF export.

## Release 1: Link Governance MVP (client: 4–6 weeks, highest priority)
This release also builds the **whole platform foundation**: loader, extraction, rule engine, dashboard, scoring, and exports.

| ID | Rule | Logic | Severity / status |
|---|---|---|---|
| L01 | Broken link | 404, 410, 5xx, timeout, DNS/connection failure | Critical |
| L02 | Bot-blocked / unverifiable | 403/429/999 or blocked by WAF, reported separately (not counted as broken) | Info, review |
| L03 | Permanent redirect | 301/308. Suggest the final destination URL | Minor |
| L04 | Temporary redirect | 302/307 | Info |
| L05 | Redirect chain / loop | More than 1 hop, or a loop. Show the full chain | Major |
| L06 | Legacy Vidyard URL | `opentext.hubs.vidyard.com/watch/{id}` → suggest `videos.opentext.com/watch/{id}`. Any other `vidyard.com` link/iframe/script is flagged without a suggestion | Major |
| L07 | Restricted reference | Any href/src containing `community.opentext.com`, `microfocus`, or `solutions/aviator` | Major, review |
| L08 | Absolute internal URL | Raw href is `https://www.opentext.com/...`. Suggest `/path?query#hash`. Exempt canonical/og/hreflang meta and other subdomains | Minor |
| L09 | Empty link | `href` empty, `#`, or `javascript:void` | Major |
| L10 | Tab behaviour *(from Vigneswari's tool)* | Internal links open in the same tab; external and resource links open in a new tab with `rel=noopener` | Minor |

**HTTP checker.** Follows redirects manually (max 10 hops) to record the chain. Sends HEAD first, then falls back to GET on 403/405. Timeout is 10 s with one retry. Concurrency is limited per host. Uses Playwright's request context (shared UA and cookies) to reduce false WAF blocks. Each unique URL is checked once per run, and `mailto:`, `tel:`, and `#anchor` links are skipped.

**Link inventory** (Link QA header). Totals for Total, Internal, External, Resource, Broken, Redirected, and Legacy links:
- **Internal:** a relative URL, or a host in the configurable `internal_hosts` list.
- **Resource:** file extensions (pdf, docx, xlsx, zip...) or resource/asset paths (configurable).
- **Legacy:** matched by L06/L07.

The full inventory table is exportable.

**Deliverables:** Broken Link Checker, Redirect Analyzer, Legacy Video Validation, Restricted Content Detection, Relative URL Validation, Link Inventory Report, plus the platform foundation and dashboard.

## Release 2: Product & Brand Governance (4–6 weeks)
**Proposed product registry columns:** Canonical Name | Approved Abbreviations | Short Forms | Legacy/Deprecated Names | Known Misspellings | Trademark (™/®) | Allowed Contexts.
This builds on the old-names Excel from the meeting.

**Matching**
- Variant patterns allow flexible whitespace and hyphens, are case-insensitive, and match longest-first with no overlaps.
- They run over visible text, headings, alt text, title, and meta description.
- Each match is classified as:
  - exact canonical or approved abbreviation: **pass**
  - case difference: **Capitalization**
  - spacing or spelling variant (❌ Load Runner → ✅ LoadRunner): **Naming**
  - legacy or deprecated name: **Legacy naming**, with a suggested replacement
- Allowed contexts such as "formerly Micro Focus" suppress the finding.

| ID | Rule |
|---|---|
| C01–C04 | Product naming, capitalization, abbreviations/short forms, legacy names (registry-driven) |
| C05 | "Micro Focus" / "MicroFocus" in copy *(Vigneswari's rule)* |
| B01 | `OpenText™` on first use in the main body (accepts U+2122 or `<sup>TM</sup>`) |
| B02 | Product trademark required per the registry |
| B03 | Trademark consistency (™ vs ® mixed; mark repeated where the standard says first use only) |
| C06 | Deprecated terminology and consistent product references across the page |

## Release 3: Accessibility & Media QA (6 weeks)

| ID | Rule |
|---|---|
| A01 | Missing `alt` attribute |
| A02 | Empty `alt=""`: passes if decorative (role=presentation, aria-hidden, or in a decorative-image allowlist), otherwise **review** |
| A03 | Duplicate alt text across different images |
| A04 | File name used as alt (`\.(jpe?g\|png\|svg\|webp\|gif)$`, `IMG_1234`, underscore/digit patterns) |
| A05 | Generic alt ("image", "banner image", "photo", "graphic"...): configurable list |
| A06 | Empty links / empty buttons (no text, aria-label, or labelled img) |
| A07 | Heading hierarchy: exactly one H1, no skipped levels, no empty headings |
| A08 | Basic WCAG indicators via **axe-core** (`axe-playwright-python`): contrast, labels, ARIA, landmarks. Summarised, not raw output |
| M01 | Broken image: HTTP status of `currentSrc`, or `naturalWidth == 0`; no `src` (lazy `data-src` exempt) |
| M02 | Missing video thumbnail / poster |
| M03 | Broken video: `<video>` with no source, a failing source URL, or a failing Vidyard embed |
| M04 | Invalid embed: iframe `src` failing or empty |

## Release 4: Template Intelligence (6–8 weeks)
- **Template detection engine.** Scores DOM component markers from `governance/templates/*.yaml`. The URL path is not reliable: product and sub-product pages share `/products/`. A manual override is always available.
- **Template definitions.** Required sections, section order, hero content (H1, subtitle, media, primary CTA), CTA placement, resource sections, and metadata standards (title, description, canonical, og tags).
- **Expected page comparison.** Preview vs staging: load both, diff the component trees (missing/extra/changed sections and CTAs), with an optional visual diff (Pillow `ImageChops`). Preview vs approved template uses the YAML definition.

**Client template list:** Product (What-Is, Product Detail, Product Category), Solution (Solution Detail, Industry Solution), Specialized (SaaS, Custom, BU).

## Release 5: Content Intelligence (8+ weeks)
- **Pre-build document QA.** Upload a .docx. `python-docx` extracts text and hyperlinks, and the same engine runs the Release 1 link rules, the Release 2 naming/trademark rules, and title and CTA standards on the document.
- **Brand voice validation.** The Claude API receives the page or document text plus the brand standards and CTA library, and returns structured findings (tone, messaging, CTA consistency). The model is pluggable and switched off by default.
- **Cross-link intelligence.** A sitemap crawl builds a site index (title, headings, terms). Page similarity (TF-IDF, with embeddings optional) then recommends related pages and missing internal links. Results are exportable.
- **Advanced reporting.** Excel/CSV/PDF exports of findings, accessibility reports, link inventory, and cross-link recommendations, plus trend analysis across runs.

## Scoring (Layer 4)
- **QA score:** 100 minus severity-weighted deductions (critical 10, major 5, minor 2, info 0), capped per rule so one repeated issue cannot zero the score.
- **Compliance score per area:** passed checks / total applicable checks.

Weights live in `rules.yaml`. Reviewer-dismissed `review` items do not count.

## Verification
- **Unit:** pytest per rule against static HTML fixtures, one fixture per rule with positive and negative cases.
- **Parity:** every finding from Vigneswari's JS tool on the sample URLs must also appear in the new tool.
- **Accuracy benchmark** (`tests/benchmark/`): a labelled set of real pages with known issues. Measures precision and recall per area against the client targets (broken links >95%, naming >90%, accessibility >80%). Re-run every release.
- **End-to-end:** start the dashboard, run each sample template URL, and check that highlights land on the correct elements, scores compute, and the Excel/CSV/PDF exports open.
- **UAT:** Vigneswari signs off on real tickets at the end of each release.
